## 오늘의 질문

### RNN과 GRU의 파라미터 수 차이가 큰 이유

RNN은 기본적으로 하나의 recurrent 변환을 사용하지만, GRU는 update/reset gate를 포함해 여러 개의 gate 계산을 수행한다. 각 gate마다 입력과 은닉 상태에 대한 가중치 행렬과 bias가 필요하므로 입력 차원(`input_size`)과 은닉 유닛 수(`hidden_size`)가 커질수록 차이가 커진다.

이번 예제의 `input_size=1`, `hidden_size=10` 기준 파라미터 수는 다음과 같다.

| 레이어 | 계산식 | 파라미터 수 |
|---|---:|---:|
| SimpleRNN | `units × (input_size + units + 1)` | 120 |
| GRU | `3 × units × (input_size + units + 1)` | 390 |
| LSTM | `4 × units × (input_size + units + 1)` | 480 |

따라서 gate 수뿐 아니라 입력·은닉 상태와 결합하는 행렬 연산의 크기가 함께 반영된다. “3배 빠르다”와 “파라미터가 3배다”는 같은 의미가 아니며, 실제 속도는 구현·하드웨어·sequence 길이·batch size의 영향도 받는다.

## 데이터 자르기

### 단변량 데이터
def split_x (dataset, size):
    aaa = []
    for i in range(len(dataset) - size + 1):
        subset = dataset[i : (i+size)]
        aaa.append(subset)
    return np.array(aaa)

bbb = split_x (a, size)

x = bbb [:, :-1, :] = bbb[:, :-1]
y = bbb [:, -1, 1] = bbb[:, :-1, :-1]
이 함수 정확히 알기

```python
def split(dataset, size):
    xs, ys = [], []
    for i in range(len(dataset) - size):
        xs.append(dataset[i:i + size])
        ys.append(dataset[i + size])
    return np.array(xs), np.array(ys)
```

예를 들어 `a = [1, 2, ..., 10]`, `size=4`이면:

- `x[0] = [1, 2, 3, 4]`, `y[0] = 5`
- `x` shape: `(6, 4)` → RNN 입력용 `(6, 4, 1)`
- `y` shape: `(6,)`

즉, 과거 4개 timestep으로 다음 1개 값을 예측한다.

### 다변량 데이터

원본이 `(time, feature)`라면 window를 만든 뒤:

- `x` shape: `(sample, timestep, feature)`
- `y` shape: `(sample, feature)` 또는 목표 feature만 선택한 `(sample,)`
- 예제의 입력은 `(batch, 4, 2)`이며 두 개의 feature를 동시에 사용한다.

로그에 적힌 `bbb[:, :-1, 1] = ...` 형태는 대입식이 아니라 shape를 설명하려던 표현으로 보인다. 실제 코드는 `x = window`, `y = 다음 timestep` 방식으로 분리해야 한다.

## 중요 체크리스트

- `input_shape=(timestep, feature)`에서 batch 차원은 보통 생략한다.
- `len(dataset) - size`는 마지막 window 다음 값을 target으로 쓰는 방식이다.
- 마지막 timestep까지 입력 window로만 쓰는 방식이면 `+1` 여부가 달라지므로 target 정의를 먼저 정한다.
- 회귀 예측에서는 마지막 `Dense` 유닛 수를 예측 target 수와 맞춘다.
- `learning_rate`가 너무 크면 loss가 튀고, 너무 작으면 학습이 느려질 수 있다.
- RNN·GRU·LSTM의 실행 속도는 파라미터 수만으로 단정하지 않는다.
