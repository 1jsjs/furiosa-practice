## [중요]

### RAG 핵심 흐름

RAG는 모델을 다시 학습시키지 않고, 질문에 필요한 외부 지식을 검색해 답변 생성에 보강하는 방식이다.

```text
질문 → 검색(Retrieve) → 관련 문서 보강(Augment) → 생성(Generate)
```

- 텍스트를 적절한 단위로 나누고(chunking)
- embedding model로 숫자 벡터로 변환한 뒤
- vector store/vector DB에 저장하고
- retriever로 관련 내용을 검색해
- 검색 결과와 질문을 LLM에 함께 전달한다.

벡터의 차원 수는 embedding model이 정하는 값이며, 수천 차원일 수 있다. “남자·여자, 공주·왕자”를 숫자 위치나 방향 관계로 표현한 예시는 임베딩 개념을 쉽게 설명하기 위한 비유로 이해한다.

### 추론·학습·메모리

- 학습: 데이터로 모델의 가중치를 변경하는 과정
- 추론: 이미 학습된 모델에 입력을 주고 출력을 받는 과정
- ChatGPT 웹 memory: 서비스가 이전 정보를 다음 대화에 활용할 수 있도록 저장·참조하는 기능
- 일반 API 호출: 이전 대화 내용을 자동으로 기억한다고 가정하지 말고, 필요한 문맥은 애플리케이션이 prompt에 전달해야 한다.

에이전트에 memory를 넣는 경우, 저장한 내용을 다음 prompt에 다시 포함시키는 방식으로 구현할 수 있다. 대화가 길어질수록 prompt가 길어질 수 있으므로 저장 범위와 요약 전략이 필요하다.

### Prompt·Model·Output과 LCEL

```text
Prompt → Model → Output
```

```python
chain = prompt | model | output_parser
response = chain.invoke(input)
```

- Prompt: 모델에 전달할 명령과 입력 형식
- Model: prompt를 처리해 답변을 생성
- Output parser: 모델 응답을 문자열 또는 원하는 구조로 변환
- LCEL: 작업 단계를 파이프라인처럼 연결하는 LangChain 표현 방식

### API 키 보안

- API 키를 Python 파일에 직접 기록하지 않는다.
- 환경변수 또는 작업 폴더의 `.env`에서 읽는다.
- `.env`는 `.gitignore`에 넣어 GitHub에 올리지 않는다.
- 키를 확인할 때 전체 값을 출력하지 말고 길이·앞부분·끝부분 일부만 확인한다.
- 키가 Git에 커밋되었거나 외부에 노출되면 즉시 폐기하고 새 키를 발급한다.
- API 키를 코드에 붙여 넣거나 실행할 때마다 사용량·비용이 발생할 수 있으므로 테스트 호출에 주의한다.
- 환경변수 변경 후 VS Code에서 인식하지 못하면 `Developer: Reload Window` 또는 프로그램 재시작을 시도한다.

오늘 실제로 노출된 키를 제거한 뒤 커밋을 수정했고, `.env` ignore 상태를 확인하여 `e58db75`로 `origin/main`에 push했다.
