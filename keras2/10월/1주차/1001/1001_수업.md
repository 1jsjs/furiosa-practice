## [중요]

### Tokenizer와 padding

- `Tokenizer.fit_on_texts()`로 단어 사전을 만들고, `texts_to_sequences()`로 문장을 정수 token sequence로 바꾼다.
- 문장마다 token 수가 다르면 `pad_sequences()`로 길이를 맞춘다.
- `padding='pre'`는 짧은 sequence 앞에 0을 채우고, `padding='post'`는 뒤에 0을 채운다.
- 길이가 다른 문장 두 개를 별도 샘플로 유지하려면 이어 붙이지 말고 padding해 `(문장 수, 최대 길이)` 배열로 만든다.
- 예측 문장도 학습 때 사용한 동일 Tokenizer와 동일한 `maxlen`, padding 설정으로 전처리한다.

### One-hot encoding과 shape

- `padded_x`: `(15, 5)` — 15개 문장, 문장당 5개 token 위치
- `reshape(-1, 1)`: `(75, 1)` — token 위치 75개를 한 열로 펼침
- OneHotEncoder 결과: `(75, 31)`
- 다시 reshape: `(15, 5, 31)`
- 70/30 분할 예: train `(10, 5, 31)`, test `(5, 5, 31)`
- 이미 `(N, 5, 31)`인 원핫 입력을 `(N, 5, 1)`로 되돌리면 원소 수가 맞지 않는다. 인코딩 후에는 그 shape를 유지하고 `input_shape=(5, 31)`로 모델에 전달한다.
- 예측 데이터는 학습 때 `fit`한 같은 OneHotEncoder에 `transform`하고 `(예측 문장 수, 5, 31)`로 reshape한다. 새 데이터에 다시 `fit`하지 않는다.
- `to_categorical()`은 token 번호가 1~9라면 0번까지 포함해 기본적으로 10열을 만든다. 0은 보통 padding용 인덱스로 남겨 둔다.

### Embedding

```text
입력 token 배열      (15, 5)
Embedding 결과       (15, 5, 100)
Embedding 가중치 표  (input_dim, output_dim)
```

- `input_dim`: 입력에서 사용할 수 있는 token 인덱스 범위의 크기. 가장 큰 token 번호가 30이면 최소 31이어야 한다.
- `output_dim=100`: token 하나를 표현할 벡터 길이. 입력 shape에서 계산되는 값이 아니라 모델 설정값이다.
- `input_length=5`: 문장당 token 위치 수. 입력 배열의 두 번째 축이 5일 때 이에 해당한다.
- 현재 `keras61_Embedding04_important.py`는 token 번호 1~30과 padding 0을 사용하면서 `input_dim=30`으로 되어 있다. 실제 token 30이 들어오면 인덱스 범위를 벗어날 수 있으므로 31 이상으로 맞춰야 한다.
- `(15, 5, 100)`은 15개 문장 각각의 5개 token이 100차원 벡터로 바뀐 결과이고, 임베딩 표 자체의 shape는 `(31, 100)`이다.

### 감성분류 예측

- 문자열을 그대로 `model.predict()`에 넣지 않는다. Tokenizer → sequence → padding → (필요하면 학습된 OHE로 transform) 단계를 거친다.
- 모델에 전달하는 예측 입력 shape는 학습 입력과 같아야 한다.
- 새 문장을 학습에 포함하려면 `docs`와 `labels`에 같은 샘플 수로 추가한다. `docs`에 문장을 추가했는데 label을 추가하지 않으면 입력·정답 개수가 달라진다.
- 이미 학습한 모델에 새 문장을 시험하려면 학습용 `docs`에 추가할 필요 없이 별도 예측 입력으로 전처리한다.
- 현재 감성분류 질문의 코드에는 `docs` 16개, `labels` 15개인 예가 있어 학습 전에 개수를 맞춰야 한다.

### 코사인 유사도와 RAG

- 코사인 유사도는 두 벡터의 방향 유사도를 `cos(θ)`로 나타낸 값이다. 유사도가 +1에 가까울수록 두 벡터 사이 각도 `θ`는 0도에 가까워진다.
- RAG의 기본 흐름은 질문 → 문서 검색 → 검색 결과를 prompt에 보강 → LLM 응답 생성이다.
- embedding은 텍스트를 벡터로 바꾸고, vector store/DB는 벡터와 문서를 저장하며, retriever는 관련 자료를 찾는다.
- embedding 차원은 사용하는 모델 설정에 따른다. 10월 1일 실습의 `text-embedding-3-small` 기본 출력은 1536차원이었고, 두 번째 예제는 `dimensions=5`로 출력 크기를 지정했다.
- 출력 차원이 작아지면 짧은 벡터가 되는 것이지, 원문 token들이 임의로 합쳐지는 것은 아니다.
