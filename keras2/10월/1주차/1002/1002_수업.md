[질문]

1. 원핫 인코딩과 sparse 라벨은 언제 쓰나요?
   ㄴ 정답을 원핫 벡터로 만들면 `categorical_crossentropy`, 정수 클래스 번호 그대로 두면 `sparse_categorical_crossentropy`를 사용한다. 마지막 출력 노드 수는 클래스 수에 맞춘다.

2. MNIST 예측 정확도를 구할 때 `y_test`에도 `argmax`를 적용해야 하나요?
   ㄴ 이 실습의 `y_test`는 이미 정수 라벨 `(10000,)`이므로 그대로 둔다. 예측 점수 `(10000, 10)`에만 `argmax(axis=1)`을 적용한다.

3. California 등 표 형식 데이터를 LSTM에 넣을 때 `reshape`만 하면 되는지, 이미지·영상도 시계열인지 질문함.
   ㄴ LSTM 입력 모양은 `(샘플, 시점, 특성)`. California의 8개 특성을 시점처럼 취급하면 `(N, 8, 1)`로 만들 수 있지만, 원래 시간 순서가 있는 데이터가 아니므로 실제 시계열 학습은 아니고 입력 모양을 맞춘 실험이다.
   ㄴ 영상은 프레임이 시간 순서대로 이어져 시계열로 볼 수 있고, 사진 한 장은 보통 공간 데이터다. 시계열에는 시간축을 따라 처리하는 `Conv1D`도 쓸 수 있다.

4. DNN·CNN·RNN·Embedding의 입력 모양과 원핫 정답/`return_sequences` 적용은 어떻게 구분하나요?
   ㄴ 모델 이름만으로 정답 인코딩이나 출력 모양이 정해지는 것은 아니다. 각 층의 입력 계약과 과제의 라벨 형식에 맞춰 정한다. 특히 `return_sequences=True`는 다음 recurrent 층에 전체 시점 출력을 전달할 때 사용한다.

5. Chroma와 FAISS의 차이는 검색 속도보다 관리 범위로 보는 게 맞나요?
   ㄴ FAISS는 주로 벡터 유사도 검색 라이브러리이고, Chroma는 벡터 검색에 문서·메타데이터 관리 기능을 함께 제공하는 쪽이다. 둘의 기능은 구성에 따라 달라질 수 있으므로 단순히 “된다/안 된다”로 단정하지 않는다.

6. 감성분류 추론용 문장을 학습 문서 목록에 바로 추가해도 되나요?
   ㄴ 학습에 넣으려면 그 문장에 대응하는 라벨도 추가해야 한다. 추론만 할 문장은 기존 토크나이저로 변환·패딩해 `predict`하고, 학습 문서·라벨 배열은 그대로 둔다.


[중요]

- 다중분류 Reuters는 클래스가 46개다. 현재 스크립트는 라벨을 `(N, 46)` 원핫으로 만들고 `categorical_crossentropy`, 출력 `Dense(46, softmax)`를 사용한다. 기사 입력은 길이 300으로 패딩한다.
- 이 Reuters 스크립트 주석의 기록 성능은 accuracy 약 0.611로, 파일 상단 목표 0.67에는 못 미친다. 기록된 실행 결과이며 이번에 재실행한 값은 아니다.
- 이진 감성분류 IMDB는 라벨 0/1과 `binary_crossentropy`, `Dense(1, sigmoid)` 조합이다. 길이 200 패딩 후 `Embedding(20000, 128)` 출력은 `(N, 200, 128)`, `Flatten` 뒤에는 `(N, 25600)`이 된다. 스크립트 주석에 적힌 모델별 점수는 과거 기록이다.
- 희소 손실은 정수 라벨을 받으므로 예측 클래스만 `argmax`로 변환한다. MNIST는 현재 코드가 정답 배열을 유지해 정확도를 계산한다.
- **확인 필요 — CIFAR-100:** 데이터 라벨은 `(N, 1)` 정수형이고 손실은 `sparse_categorical_crossentropy`인데, 현재 파일은 `y_test = np.argmax(y_test, axis=1)`을 수행한다. 각 행에 값이 하나뿐이라 결과가 전부 0이 되어 수동 accuracy가 잘못 계산될 수 있다. `y_test`를 변형하지 않고 예측만 `argmax`한 뒤 비교해야 한다. 파일은 이번 정리에서 수정하지 않았다.
- 표 데이터의 열을 임의로 LSTM 시점으로 바꾼 것은 모양 실험이다. California `(N, 8, 1)`, Diabetes `(N, 10, 1)`처럼 입력할 수 있어도, 특성 열에 시간적 순서가 생기는 것은 아니다. 이미지도 행을 시점으로 간주할 수는 있지만 그 해석의 한계를 기억한다.
- MNIST Reshape 실습은 `(N, 28, 28)` → `Dense(280)` → `(N, 28, 280)` → `Reshape(28, 28, 10)`으로 CNN에 전달하는 구성이다. 다른 파일은 Dense 뒤 `Reshape`, CNN, LSTM을 연결한 확장 실험이다. 주석에는 각각 accuracy 0.989, 0.992가 기록돼 있지만 해당 실행을 다시 검증한 것은 아니다.
- 벡터 검색 도구를 고를 때 먼저 확인할 것은 검색만 필요한지, 문서와 메타데이터 저장·관리도 필요한지다. FAISS와 Chroma의 역할을 구분하되 제품 기능을 절대적인 이분법으로 단순화하지 않는다.


[실습]

1. `keras62` — Reuters 다중분류, IMDB 이진 감성분류
   ㄴ Reuters: 정수 토큰 시퀀스를 길이 300으로 패딩하고, 46개 클래스 원핫 라벨과 양방향 LSTM 분류기를 구성.
   ㄴ IMDB: 정수 토큰을 길이 200으로 패딩하고 Embedding + Flatten + DNN으로 감성분류. LSTM/GRU 대안 코드도 파일에 주석으로 남아 있음.

2. `keras63` — MNIST, Fashion-MNIST, CIFAR-10/100의 sparse 분류
   ㄴ 원핫 변환 없이 정수 라벨과 `sparse_categorical_crossentropy` 사용. 출력 노드 수는 각각 10, 10, 10, 100.
   ㄴ MNIST 수동 accuracy 계산에서 정답 `argmax`를 제거한 수정 내용을 채팅에서 확인. CIFAR-100의 동일 유형 평가 코드는 아직 점검/수정 필요.

3. `keras64` — 표 데이터에 LSTM 입력 모양 적용
   ㄴ California: 8개 특성을 `(N, 8, 1)`로 reshape, LSTM 회귀 출력 1개. 파일 주석에는 DNN/LSTM 비교 결과가 기록돼 있음.
   ㄴ Diabetes: 10개 특성을 `(N, 10, 1)`로 reshape해 회귀 실험.
   ㄴ Boston·Dacon·Bike·Cancer·Santander·Wine·Covtype·Digits 파일은 현재 비어 있는 시작 파일인지 후속 확인.

4. `keras65` — MNIST Dense/Reshape/CNN 및 LSTM 결합 실험
   ㄴ Dense 출력 차원을 맞춘 뒤 `Reshape`로 CNN 채널 축을 만들고, 별도 스크립트에서는 중간 특징을 LSTM에도 전달.
   ㄴ 스크립트 주석의 결과는 참고 기록으로만 보존.

5. 감성분류 추론 문장 처리
   ㄴ 기존 tokenizer로 새 문장을 정수 시퀀스로 변환하고 학습 때와 같은 길이로 패딩해 예측. 학습 데이터에 추가하는 경우에만 대응 라벨도 함께 추가.
