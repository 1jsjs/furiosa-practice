[질문]

1. `RecursiveCharacterTextSplitter`의 `chunk_size`와 실제 청크 길이가 다른 이유는?
   ㄴ `chunk_size`는 토큰 수가 아니라 이 코드의 기본 길이 함수 기준 문자 수다. `separators`가 문단·줄·공백 경계에서 먼저 나누고, `chunk_overlap`은 이웃 청크에 문맥을 겹쳐 넣으므로 결과 길이는 모두 정확히 300자가 되지 않는다.

2. `langchain-community`를 설치했는데 `langchain.community`를 찾지 못하거나 문서 로드가 실패하는 이유는?
   ㄴ 패키지명과 import 모듈명은 다르다. Python에서는 `langchain_community.document_loaders`를 import한다. 별도 실행에서는 import 다음 `TextLoader`가 파일을 못 찾았는데, `samsung_out.look.txt` 오타를 실제 파일명 `samsung_outlook.txt`로 맞추는 것이 원인이었다. 실행 작업 폴더에 따라 상대경로도 달라진다.

3. Jena CNN 학습에서 “예측 13개, 정답 144개” 또는 MAE shape 오류가 난 이유는?
   ㄴ 입력 특성 수 13과 예측 시점 수 144를 혼동한 것이다. CNN 입력 채널은 13개 특성이지만 회귀 출력은 다음 144개 기온값이어야 한다. 정답과 모델 출력의 shape도 같아야 한다.


[중요]

- `Document`는 본문 `page_content`와 출처 등의 `metadata`를 가진다. 청킹은 본문을 나누며, 각 청크에 문서 메타데이터가 이어진다.
- `chunk_size=300`은 300토큰을 뜻하지 않는다. 현재 `RecursiveCharacterTextSplitter`는 문자열 길이를 기준으로 나누고, 문단→줄→공백→문자 순으로 경계를 시도한다. 청크 길이가 다소 짧거나 다르게 나오는 것은 경계와 overlap 처리의 결과다.
- Chroma에 저장할 때와 다시 열 때 동일한 `persist_directory`, `collection_name`, embedding 설정을 사용해야 한다. 오늘 코드는 `text-embedding-3-small`을 사용했고, Chroma11은 `_db/Chroma11/`·`chroma11`, Chroma12는 `_db/Chroma12/`·`chroma12`에 저장한다.
- Chroma11은 삼성·엔비디아 문서를 각각 청크 크기 300, overlap 100으로 나누어 저장하는 실습이다. 저장 문서 수는 스크립트 주석상 각 9개(합계 18개)이며, 로드 뒤 유사도 검색은 `k=2`.
- Chroma12는 폴더의 텍스트 파일 3개를 모아 청크 크기 300, overlap 10으로 분할한다. 주석에 청크 52개, 임베딩 벡터 길이 1536, 기본 검색 결과 4개, retriever `k=2`가 기록돼 있다.
- Jena는 과거 144개 시점 입력·출력을 위한 sliding window를 만든다. 13개 기상 특성을 포함한 입력 `(N,144,13)`을 CNN 입력 `(N,12,12,13)`으로 접고, 정답은 `(N,144)`로 유지한다. 따라서 마지막 층은 `Dense(144, activation='linear')`이고 `x_predict`도 `(1,12,12,13)`, `y_cor_scaled`도 `(1,144)`여야 한다.
- Jena 오류 해결의 핵심은 모델 출력·학습 정답·평가 정답을 모두 144개 값으로 맞추는 것. `y`를 `(N,12,12,1)`로 바꾸면 Dense 출력 및 MAE와 다시 shape이 어긋난다. 현재 커밋된 코드는 `y`를 `(N,144)`로 두는 형태다.
- 144개 값은 10분 간격 데이터라면 24시간 분량이다. 다만 12×12로 접은 입력은 CNN에 시점의 앞뒤 경계를 공간 이웃처럼 보이게 한다. shape 오류 해결과 모델 표현의 타당성·예측 성능은 별개다.
- 스크립트 주석의 Jena CNN 기록은 R2 약 -3.42, MSE 약 48.18, RMSE 약 6.94, 학습 약 128.63초다. 낮은 R2이므로 성능이 좋다는 뜻이 아니며, 이번 로그 정리에서 재실행한 수치는 아니다. 당시 실행 로그에는 약 2.8GB 메모리 할당 경고도 있었다.
