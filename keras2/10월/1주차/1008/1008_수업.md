[질문]

1. 서로 다른 모양의 데이터 여러 개를 한 Keras 모델에 넣으려면?
   ㄴ Functional API에서 입력마다 `Input(shape=...)`와 branch를 만들고, 샘플 수를 맞춘 뒤 `[x1, x2, ...]` 순서로 `fit`/`evaluate`/`predict`에 전달한다. 이번 오류는 `x2_datasets.transpose`를 호출하지 않아 배열 대신 메서드가 전달된 것.

2. PDF RAG 챗봇에서 벡터 저장소 문서 수가 0이거나 답변이 논문 근거를 못 찾는 이유는?
   ㄴ 저장·로드 시 컬렉션 이름이 대소문자까지 일치해야 한다. 또 `k=2`면 상위 두 청크만 모델에 전달되므로, 관련 근거가 4번째 검색 결과라면 모델은 그 근거를 볼 수 없다.

3. 임베딩 가중치 로딩이 100%인데도 챗봇이 바로 뜨지 않는 이유는?
   ㄴ 가중치 로딩 이후에도 PDF 청크들의 임베딩 계산과 Chroma 저장이 남을 수 있다. 이 단계는 별도 진행 표시가 적을 수 있어, 그 로그만으로 완료나 오류를 단정하지 않는다.

4. Gradio의 `.gradio/certificate.pem`은 올려도 되나요?
   ㄴ 파일명이나 첫 줄만으로 업로드 안전성을 단정하지 않는다. 개인 키 헤더가 있는지 내용을 공개하지 않고 확인하고, 인증서가 내부 정보인지도 살핀다. 로컬 설정·인증서가 든 `.gradio/` 폴더는 Git에 올리지 않도록 ignore한다.

5. 짧은 후속 질문이 논문 챗봇에서 검색되지 않는 이유는?
   ㄴ 현재 `answer_invoke(message, history)` 구현은 `history`를 쓰지 않고 새 메시지만 검색 체인에 넘긴다. “어텐션의 개념” 같은 후속 질문은 독립 검색어가 되어 문맥을 놓칠 수 있다.


[중요]

- 다중 입력 앙상블은 각 입력 배열의 행 수(샘플 수)와 모델 입력 순서를 맞춘다. 스크립트 1·2는 각 branch의 특징을 `Concatenate`로 합친 뒤 회귀 출력 1개를 만든다.
- 앙상블 실습의 입력 모양은 `x1: (100,2)`, `x2: (100,3)`, `x3: (100,4)`, 타깃은 `(100,)`. 모델 3은 세 입력을 합쳐 타깃 두 개를 출력하고, 학습 시 `[y1, y2]`를 출력 순서에 맞춰 전달한다.
- 모델 3에는 계산해 놓고 최종 출력에 연결하지 않은 `last_dense1`, `last_dense2`가 있다. 현재 출력 두 개는 모두 `merge3`에서 직접 갈라진다. 의도된 구조인지 후속 확인 대상이며, 이번 정리에서 코드는 수정하지 않았다.
- 세 앙상블 파일의 예측 입력 예시는 주석 처리돼 있어, Git에 들어간 파일만으로 신규 샘플 예측 실행이 끝났다고 볼 수 없다. 모델 학습 결과/점수도 로그에서 확인되지 않아 재실행한 것으로 기록하지 않는다.
- RAG 기본 흐름: PDF 로드 → 청크 분할 → 임베딩 → Chroma 저장 → Retriever 검색 → 문서 체인/LLM → Gradio 대화 UI. 논문 전체 요약은 관련 청크만 찾는 일반 RAG 질의와 별도의 요약 설계가 필요할 수 있다.
- Transformer PDF는 청크 `chunk_size=200`, `chunk_overlap=0` 설정에서 로그상 245개 청크가 생성됐다. 검색 결과 중 아키텍처 설명이 4번째였는데 기존 `k=2`는 앞의 두 청크만 전달해 근거가 빠졌다. 코드에는 이후 `k=5` 설정이 반영돼 있다.
- Chroma 저장·로드는 같은 `persist_directory`와 정확히 같은 `collection_name`을 써야 한다. 대소문자 차이도 별도 컬렉션을 가리킬 수 있다. `from_documents`를 매 실행마다 호출하면 중복 색인될 수 있어 색인과 DB 로드를 분리하는 편이 안전하다.
- 임베딩 모델을 바꾸면 같은 컬렉션에 섞지 않는다. `text-embedding-3-small`과 로컬 `Qwen/Qwen3-Embedding-0.6B`는 차원과 벡터 공간이 다르며, 같은 차원의 모델끼리도 호환된다고 볼 수 없다. 현재 RAG 코드가 기존 `Chroma13`을 재사용하므로 모델 변경 시 새 DB/컬렉션을 사용하는지 확인이 필요하다.
- PDF 페이지 메타데이터의 인덱스는 0부터 시작할 수 있다. 프롬프트에 `[p.{page}]`를 쓰는 경우 사람이 보는 PDF 페이지와 맞는지 확인하고, 필요하면 색인 전에 +1 보정한다. 현재 스크립트의 보정은 확인되지 않았다.
- RAG 프롬프트는 검색 근거가 없을 때 모른다고 답하도록 해야 한다. 로그에서 한 실험용 프롬프트에는 근거가 없어도 지어내라는 지시가 있었고, 후속 대화에서는 이를 근거 기반 응답으로 바꾸도록 권했다.
- `Gradio demo.launch(share=True)`는 외부 공유 링크를 만들 수 있으므로 공개 의도가 없으면 공유 옵션을 켜지 않는다. `.gitignore`에는 `/.gradio/`가 추가되어 로컬 Gradio 폴더를 제외한다. `*.pdf`도 ignore 규칙에 포함됐다.
- 로컬 임베딩 비교 실습 주석에는 `BAAI/bge-m3`, `Qwen/Qwen3-Embedding-0.6B`가 각각 1024차원으로 적혀 있고, 두 모델은 CPU 설정이다. 파일의 주석 결과이며 본 정리에서 재측정한 값은 아니다.
